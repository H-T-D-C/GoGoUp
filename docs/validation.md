# 動作確認記録

## 確認環境

2026-10-16にユーザーから共有された専用サーバーのログを診断資料として確認した。

- Minecraft 26.1.2 / Fabric Loader 0.19.5 / Java 25
- Fabric API 0.155.3+26.1.2 / GoGoUp 1.0-beta
- 共有ログにはJEIも記載されている。Mod未導入クライアントでの互換性を実証した記録とは区別する。

生ログは個人名・UUID・ローカルパスを含むため、この文書には必要な結果だけを記載する。共有用の `test/` はGit管理対象外。

## 確認できた結果

| 項目 | 根拠・確認範囲 |
| --- | --- |
| 通常の手設置 | アイテム使用イベント登録の撤去後、ユーザーから設置できるとの報告あり |
| 低高度でのコマンド設置 | 上限内の `/setblock` 成功を共有ログで確認 |
| 設定上限より上へのコマンド設置 | ユーザーから拒否されたとの報告あり |
| 稼働中の上限変更 | 最終共有ログの22:26台にY=200、続いてY=300への変更成功メッセージあり |
| 高度298・306へのコマンド設置 | 最終共有ログに成功記録あり。高度306の設置は上限200への変更前 |
| サーバー起動・終了 | 最終共有ログで正常な起動、各ディメンションの保存・終了を確認 |

最終共有ログにGoGoUp由来のエラーはない。WindowsのPerfOSレジストリ値についての警告は、Modの設置処理とは別のもの。

## 設置不具合への対応

初期実装は全アイテムを対象とする `ItemEvents.USE_ON` ハンドラーを登録していた。診断では、Survivalへ切り替えた後も石の操作結果が `Pass[]` になり、通常の設置が進まないことを確認した。

その登録を撤去し、`BlockItem.place` と `BucketItem.emptyContents` を個別のMixinで制限する方式へ変更した。その後、ユーザーから設置の復旧報告を受けた。調査用の操作ログMixinは削除済み。

## リリース前に確認する項目

- 全3ディメンションをMod未導入のバニラクライアントで描画・設置・破壊できること。
- 設定値0、300、2031で、上限ちょうどを許可し、上限+1を拒否すること。
- プレイヤーのバケツ、`/setblock`、`/fill` も同じ境界を守ること。
- 接続したまま上限を上下させ、既存ブロックを保持して設置可否だけが切り替わること。
- 高所のブロックが保存・再起動・再接続・チャンク再読込後も残ること。
- 不正JSON、範囲外の整数、設定保存・再読込失敗で意図したエラー処理になること。
- 既存ワールドの地形・ネザー屋根、新規チャンク生成、メモリ使用量を確認すること。

自動テストは未導入。`gradlew.bat build` の成功はコンパイル・パッケージ作成の確認であり、上記の実プレイ検証を代替しない。
